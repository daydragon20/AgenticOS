Start hier · fundament Het hele systeem

Wat is een agent eigenlijk?

Een agent = waarnemen → beslissen → handelen. Een workflow volgt vaste stappen; een agent redeneert. De Director is je orkestrator, de 6 anderen zijn specialisten. Jouw systeem is dus een orkestratie-graaf, geen 7 losse chatbots.

Bouw bij Rocadelo

Teken je 7 agents als één graaf: wie roept wie aan, waar loopt elke agent (n8n / Claude API / MCP), en welke data deelt iedereen.

Checklist
  • Graaf getekend (op papier mag)
  • Elke agent heeft één zin: "wat doe ik"
  • De pijlen tussen agents kloppen
Leg hardop uit — vertel in 60 sec aan Matias waarom dit een orkestratie is en geen chatbot.
Daarna: je legt in één plaat uit hoe een lead door je systeem stroomt.

Concept Alle agents

MCP — hoe een agent dingen kan dóén

MCP is de standaard waarmee Claude met tools en data praat (client ↔ server; tools / resources / prompts). Zonder MCP schrijf je voor elke koppeling lijmcode; mét MCP plug je in. Dít is letterlijk "Claude toegang geven tot meer".

Bouw bij Rocadelo

Gebruik je bestaande n8n-MCP. Laat Claude er één echte actie mee doen (bv. een rij in Supabase lezen of een workflow triggeren). Start met wat je al hebt — €0.

Checklist
  • n8n-MCP verbonden en getest
  • 1 echte actie via MCP uitgevoerd
  • Tool-lijst per agent gemaakt (Unipile, Supabase, ...)
Leg hardop uit — waarom noemen ze MCP "de USB-C van AI"?
Daarna: je weet welke van je 7 agents welke tool nodig heeft.
2
Orkestratie Director

De Director — delegeren in de praktijk

De grote keuze: subagent (dynamische redenering, schone context) vs n8n-stap (vaste, voorspelbare pipeline). Vuistregel: vaste volgorde → n8n; "het hangt ervan af"-beslissing → agent.

Bouw bij Rocadelo

Schrijf de beslislogica van de Director: wanneer gaat een lead van Signal Detector → Lead Scorer → Message Writer? Wat triggert de Reply Handler?

Checklist
  • Beslisboom Director uitgeschreven
  • Per stap gemarkeerd: n8n of agent?
  • 1 edge-case bedacht (wat als de score laag is?)
Leg hardop uit — het verschil n8n vs subagent, met een Rocadelo-voorbeeld.
Daarna: voor elke overgang weet je waar die thuishoort.
3
Eén specialist écht goed Lead Scorer

De Lead Scorer — het patroon dat je 6× hergebruikt

Bouw één agent end-to-end: heldere prompt + tool + gestructureerde output (JSON). Dit is het sjabloon waarmee je daarna de andere specialisten klopt.

Bouw bij Rocadelo

Input: een LinkedIn-profiel (Unipile-data) → Output: een score + reden in vast JSON-formaat, via de Claude API.

Checklist
  • Prompt geschreven
  • JSON-schema vastgelegd
  • 3 testprofielen gescoord — reden klopt
Leg hardop uit — waarom is JSON-output betrouwbaarder dan vrije tekst?
Daarna: je kopieert dit patroon naar Signal Detector en Message Writer.
4
Geheugen & state Performance Analyst

Wat de agents delen

Agents onthouden niets tussen runs — tenzij je het opslaat. Je database (Supabase / SQLite) is het gedeelde geheugen. De Performance Analyst leest die geschiedenis terug.

Bouw bij Rocadelo

Ontwerp het schema dat alle 7 agents lezen/schrijven: leads, scores, berichten, replies, meetings, resultaten.

Checklist
  • Tabellen benoemd
  • Per agent: "wat schrijf ik / wat lees ik"
  • 1 lead handmatig door het schema gevolgd
Leg hardop uit — waar zit het "geheugen" van je systeem, en waarom daar?
Daarna: je ziet hoe één lead z'n hele reis in de database achterlaat.
5
Betrouwbaarheid & rem Reply Handler

Niet alles automatisch

Rate limits, proxies (NodeMaven), foutafhandeling en human-in-the-loop. Sommige acties — zoals een echte reply versturen — wil je niet blind automatiseren. Eerst jij goedkeuren.

Bouw bij Rocadelo

Markeer per agent: auto vs jij-keurt-goed. Bouw één approval-stap in vóór elk uitgaand bericht.

Checklist
  • Auto/handmatig-lijst per agent
  • Approval-stap vóór outreach
  • Plan: wat als LinkedIn rate-limit geeft?
Leg hardop uit — waarom automatiseer je de Reply Handler níét volledig?
Daarna: het kan draaien terwijl je slaapt — de risicovolle acties passeren een mens.
6
Samen + de radar Performance Analyst

Live zetten en bijhouden

Deploy-denken (Hetzner draait het 24/7), monitoring (de Performance Analyst is je dashboard), en de meta-gewoonte: als er een glanzende nieuwe agent-repo verschijnt — dient die Rocadelo nu, of gaat hij naar de radar?

Bouw bij Rocadelo

Zet de Performance Analyst op één simpele metric (leads → replies → meetings). Open je Tech Radar en park je eerste 3 verleidingen.

Checklist
  • 1 metric live zichtbaar
  • Tech Radar geopend
  • 3 verleidingen geparkeerd
Leg hardop uit — welke ene metric beslist of Rocadelo werkt?
Daarna: je meet je systeem én beoordeelt nieuwe tools zonder af te dwalen.

De regel die je beschermt

Elke verleiding die tijdens deze sprint langskomt — een nieuwe repo, een ander framework, een glanzende tool — gaat niet in je hoofd. Hij gaat naar de Tech Radar. Eén pad tegelijk. De rest wacht netjes op zijn beurt.
